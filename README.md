# google-accounts-mcp

An MCP server that lets your AI agents use several Google accounts at once: personal gmail.com accounts and Google Workspace accounts from any organization. You decide what each agent connection can do in each account, and every tool call is recorded.

You deploy it to your own Cloudflare account, with your own Google Cloud OAuth client. Gmail comes first; other Google services follow.

**Status:** owner sign-in through Cloudflare Access and MCP connections for Claude, Claude Code, and ChatGPT are implemented. The owner can manage Google accounts and set each connection's tools to Not allowed, Ask first, or Allowed. Connections start with no access. Each connection lists only account tools set to Ask first or Allowed on at least one account. The server announces a changed tool list to clients that listen. `list_accounts` returns accounts with at least one tool set to Ask first or Allowed. `list_labels` lists an account's Gmail labels, and `search_threads` searches the mail of one account with a Gmail query; an agent calls it once for each account. With Ask first, either tool returns an approval link without contacting Google. The signed-in owner approves or rejects on that page; approving runs the call once, and the agent collects its outcome with `get_approval`. Approvals expire after one hour. Tokens, pending arguments, and retained results are encrypted in D1. Every tool call is recorded; a missing outcome means the result is unknown. A search makes one request to Gmail for the list and one for each thread, at most 26, which fits the subrequest limit that Cloudflare documents for the Workers Free plan. A page for viewing these records and more Gmail tools are planned in the [issues](../../issues).

Before deploying this version, apply all pending migrations through `migrations/0005_approvals.sql` to the deploy's D1 database with `pnpm exec wrangler d1 migrations apply DB --remote`. This includes `migrations/0004_permissions_and_calls.sql` if it has not been applied. Use the same configuration and environment as the Worker. Deploy the code only after the migrations succeed. Migration 0005 preserves existing allowed permissions. Without migration 0005, connection pages fail closed; revoking a connection, removing an account, and setting a tool to deny return HTTP 503 and change nothing. Account tool calls fail without an audit record. Deploying this version creates a cron trigger (`*/10 * * * *`) that cleans up approvals every ten minutes.

An agent that controls a browser where the owner is signed in can approve its own call or change its own settings. The server cannot distinguish those browser actions from the owner's actions.

Browser tests use Chromium. After `vp install`, run `pnpm exec playwright-core install chromium` once before `vp test run`. CI installs Chromium and its system dependencies.
