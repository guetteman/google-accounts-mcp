# google-accounts-mcp

An MCP server that lets your AI agents use several Google accounts at once: personal gmail.com accounts and Google Workspace accounts from any organization. You decide what each agent connection can do in each account, and every tool call is recorded.

You deploy it to your own Cloudflare account, with your own Google Cloud OAuth client. Gmail comes first; other Google services follow.

**Status:** owner sign-in through Cloudflare Access and MCP connections for Claude, Claude Code, and ChatGPT are implemented. The owner can manage Google accounts and set each connection's tools to Not allowed, Ask first, or Allowed, individually or for a whole account. Tools are grouped by job. Changing a whole account to Ask first or Allowed asks for confirmation. Connections start with no access. Each connection lists only account tools set to Ask first or Allowed on at least one account. The server announces a changed tool list to clients that listen. `list_accounts` returns accounts with at least one tool set to Ask first or Allowed. Calling a denied tool on one of those accounts returns `tool_not_allowed` with a link to the connection's settings. An account with every tool denied stays hidden. `list_labels` lists an account's Gmail labels, and `search_threads` searches the mail of one account with a Gmail query; an agent calls it once for each account. `read_thread` reads a thread as plain text, with attachment names and pages for long threads. Reading leaves unread mail unread. `change_labels` archives threads, marks them read or unread, and adds or removes labels; it refuses the trash and spam labels. One call names at most 15 threads so that approving it stays within the 50 subrequests of the Workers Free plan. `create_draft` writes a new draft or a reply with a plain text body; nothing is sent. Repeating the same arguments from one connection within seven days returns the first result, a running or unknown status, or its pending approval. Use `duplicate: 2` to create another copy on purpose. An unknown outcome asks the owner to look in Gmail before requesting another copy. `trash_messages` moves named messages to the trash, `restore_messages` takes them out, and `delete_messages` deletes them permanently. Each accepts up to 15 message IDs from one account. Permanent deletion cannot be undone. Their results list the messages that changed, with label IDs for trash and restore. `not_found` lists IDs that the account does not have, and `unconfirmed` lists IDs for which Google did not confirm the change; retry those IDs. Empty lists are omitted. A call returns an error when Google confirms the change for none of the messages. With Ask first, an account tool returns an approval link without contacting Google. The signed-in owner approves or rejects on that page; approving runs the call once, and the agent collects its outcome with `get_approval`. Approvals expire after one hour. Tokens and the arguments and results retained for approvals are encrypted in D1. Same-call records hold only a keyed identity, a claim, times, and Gmail IDs. Every tool call is recorded; a missing outcome means the result is unknown. A search makes one request to Gmail for the list and one for each thread, at most 26, which fits the subrequest limit that Cloudflare documents for the Workers Free plan. A page for viewing these records and more Gmail tools are planned in the [issues](../../issues).

Before deploying this version, apply all pending migrations through `migrations/0006_same_call.sql` to the deploy's D1 database with `pnpm exec wrangler d1 migrations apply DB --remote`. This includes migrations 0004 and 0005 if they have not been applied. Use the same configuration and environment as the Worker. Deploy the code only after the migrations succeed. Migration 0005 preserves existing allowed permissions; migration 0006 preserves existing approvals and adds the records that prevent repeated drafts. Without migration 0005, connection pages fail closed; revoking a connection, removing an account, and setting a tool to deny return HTTP 503 and change nothing. Account tool calls fail without an audit record. Deploying this version creates a cron trigger (`*/10 * * * *`) that cleans up approvals and expired same-call records every ten minutes.

An agent that controls a browser where the owner is signed in can approve its own call or change its own settings. The server cannot distinguish those browser actions from the owner's actions.

Browser tests use Chromium. After `vp install`, run `pnpm exec playwright-core install chromium` once before `vp test run`. CI installs Chromium and its system dependencies.
